## 0. Context — 이 설계가 나온 배경

- **지원자:** RSM 신한회계법인 2년차 KICPA. (실무 경험은 **외감·감사 중심**)
- **이력:** 딜로이트 안진 **감사부문** 경력직 지원 → 면접 후 불합격. → 이번엔 **Tax/세무본부**로 전환 지원.
- **전환:** 이후 AI 개발에 몰입 → **세무조정 자동화 + 세법 리서치** PoC 직접 개발.
- **벤치마크:** 법무·세무 AI **8개사**(넥스트·LexisNexis·네플라·LBOX·슈퍼로이어·더존·AiLex·Copilot) 정밀 분석.
- **기준 골격:** 회계사 업무 활용사례 발표의 *멀티 에이전트 병렬 교차검증* 구조를 차용.

### 차용한 기준 골격 (요약)
```
쟁점 입력 → MCP(과거 파일/기록 DB)에서 컨텍스트 수집
        → 오케스트레이터가 3개 Agent 병렬 실행 (NotebookLM=정확 / 법령 MCP=원문·Ground Truth / WebSearch=최신)
        → 교차검증 → 답변 작성 → 자문기록 저장 → 안내문(docx)
강조점: 환각 방지 · Ground Truth · 출처표기 · 사내 보안정책 준수
```

## 1. WHY — 왜 만드는가

### 1-1. 시장의 진실 (8개사 벤치마크가 알려준 것)
- **컴플라이언스는 이미 정복됐다**: 더존 ONE AI가 법인세무조정·신고·일반 세법 Q&A를 *무료·ERP연동·대량*으로 제공("3시간→5분"). 여기서 경쟁하면 진다.
- **그러나 업계가 한목소리로 비워둔 자리가 있다**: 더존("반복업무 → 세무사는 컨설팅 집중")·AiLex("문서 노가다 대신 승소 전략")까지 — **"AI는 반복, 사람은 전략"**. 즉 **고부가 전략·복잡 판단**은 모두가 사람 몫으로 남겨둠.
- 그 빈 자리가 **정확히 딜로이트 안진이 파는 영역**(전략 자문)이며, 그래서 *확장(scale)이 안 되는* 고부가 자문을 AI가 거드는 것이 가치.

### 1-2. 왜 안진(Tax 본부)에 자산인가
- 반복작업은 더존에 맡기고, 회계사를 **고부가 전략 자문에 재배치** — 그 전략 업무를 *표준화·재현·근거화*.
- "AI를 *쓰는* 법인"을 넘어 **"AI를 *만들 줄 아는* 회계사"** 보유.
- 빅4는 M365·Copilot 스택 → 본 솔루션은 그 생태계와 *경쟁이 아니라 접목* 가능한 **세무 도메인 레이어**.

### 1-3. 왜 (다른 사람이 아니라) 내가 — "감사로 검증을 체화한 회계사"
- **회계사 × AI 직접 개발 = 희소 교집합.** 어디가 쟁점이고 어디서 AI 환각이 위험한지 판별 가능.
- **감사 배경 = 숨은 무기**: 감사 = 검증·직업적 회의(professional skepticism)·데이터 정합성·오류 적발. 이것이 8개사 누구도 못 가진 **"계산층 Ground Truth 검증"**의 원천 역량.
- 작년 탈락 후 **1년간 PoC로 증명**(조정·리서치). 말이 아니라 결과물.

## 2. WHAT — 무엇을 만드는가

> **정의:** **"감사로 검증을 체화한 회계사가 만드는, 검증 가능한 법인세 *전략* AI."**
> 절세 전략 시나리오를 생성하되, 각 방안의 **과세 리스크와 방어논리를 근거와 함께 검증해** 제시한다. **최종 판단은 회계사(HITL).**

### 2-1. 3대 기능 블록 — *전략을 킬러로 상향, 조정·리서치는 실력 증거*
| 블록 | 역할 | 성격 | 상태 |
|---|---|---|---|
| ① 세무조정 자동화 | **실력 증거(PoC)** — "더존이 회사 차원에서 하는 걸 나는 혼자 만든다" | 계산층(결정론) | PoC 보유 |
| ② 세법 리서치 | **실력 증거(PoC)** + 전략의 근거 공급 | 해석층(예규·판례) | PoC 보유 |
| ③ **절세 전략 시나리오 생성기** | **★ 킬러** — 과세·방어 양면 + 근거 + 검증 | 판단층(정답 없음) | 신규(설계) |

### 2-2. 차별점 — "검증 가능한 세무 *전략* AI" (8개사 대비)
- 업계 정석 아키텍처(**Skills/워크플로 + grounding·인용 + 팩트체커 검증 + HITL/Agentic + 맥락 메모리**)와 **본 설계가 정확히 일치** → 설계 정당성 확보.
- **아무도 못 가진 우리 영역**: 정답이 존재하는 **세무 계산층 Ground Truth 검증** + **회계사 직접 개발**. (법률 6사 = 해석층 인용검증까지 / 더존 = 공제 *적용확인*까지 / **계산검증 + 고차 전략판단은 8개사 공백**)
- 핵심 차별 3축: ① **과세·방어 양면** ② **검증 가능**(계산+근거) ③ **회계사 직접 개발**.

### 2-3. 킬러 데모 — 절세 전략 시나리오 생성기 (★ 구조 중심)
| 요소 | 내용 |
|---|---|
| 입력 | 가결산 재무데이터 + 상황 설명 텍스트 (둘 다) |
| 처리 | 절세 시나리오 생성 → 각 방안별 **과세논리 vs 방어논리 양면** 제시 |
| 근거 | **실제 법령·예규·판례 인용 + 출처표기**(grounding) |
| 검증 | ① 절세효과 **계산** 검증(Ground Truth) + ② 방어논리 **근거** 검증 |
| 판단 | AI는 선택지·수치·근거만, **최종 판단은 회계사(HITL)** |
| 소재 | 가볍게(예: 세액공제·감면 유불리) — **특정 주제 깊이가 아니라 "작동 구조"를 보여주는 데 집중** |

> *왜 "구조 중심"인가*: 2년차가 특정 절세 주제로 깊이 경쟁하면 후벼파임. **시스템을 설계했다는 "구조" 자체가 "AI 만드는 회계사" 정체성의 진짜 flex.**

## 3. HOW — 어떻게 만드는가

### 3-1. 아키텍처 (기준 골격을 법인세 전략으로 확장)
```
[데이터·컨텍스트 레이어]
  가결산 재무·전표 · 과거 신고/조정내역(거래처 단위 메모리) · 국가법령정보 MCP · 예규·판례 DB
            │
[오케스트레이션]
  Claude Code ── 작업 분해 · 에이전트 병렬 실행 · 결과 통합 (= LexisNexis "Work" / 슈퍼로이어 "계획→결과물")
            │
   ┌────────┼──────────────────────────────┐
[에이전트]  ① 조정 Agent(PoC)   ② 리서치 Agent(근거 공급)   ③ ★전략 Agent(절세 시나리오)
            │                    │                              │ 과세논리 vs 방어논리 + 근거 인용
[검증 레이어]  ① 계산 Ground Truth 대조      ② 근거(법령·판례) 출처·실재 검증      ③ human-in-the-loop
            │
[산출 레이어]  절세 시나리오 리포트(방안별 효과·과세리스크·방어논리·근거) · 자문메모(docx) · 자문기록 저장
```

### 3-2. 신뢰성 설계 (면접에서 후벼팔 지점 선제 방어)
- **계산 검증(감사 DNA)**: 절세효과·세법 한도를 코드 Ground Truth와 대조, 불일치 시 자동 플래그. → "세무 팩트체커/검산기"(슈퍼로이어 팩트체커의 세무판, *계산*이라 더 강함).
- **근거 검증·출처표기**: 방어논리의 법령 조문·판례 번호를 **의무 인용**(LBOX·슈퍼로이어식 grounding 가시화).
- **과세·방어 양면**: 리스크까지 스스로 까는 구조 → 깊이 의심 방어 + 감사적 회의 증명.
- **HITL**: AI는 시나리오·수치·근거까지, **결정·서명은 회계사**. ("AI가 결정"이 아니라 "회계사 판단 근거를 10배로 확장")
- **보안**: 고객 재무정보 민감 → 사내 보안정책 준수, 접근통제·프라이빗 배포(AiLex 폐쇄형·슈퍼로이어 비학습 참조).

### 3-3. 정량 효과 (ROI 틀 — Copilot KPI 차용)
- 절세 시나리오 도출 시간, 근거 리서치 시간, 자문메모 초안 시간의 절감률(%)을 데모에 수치로 표기.

### 3-4. 증거와 로드맵
- **PoC(증거)**: 이미 작동하는 세무조정 자동화 + 세법 리서치.
- **면접 전 산출**: **설계도 + 화면 목업**(2~3개 흐름). *작동 데모는 다음 단계.*
- **로드맵**: (1) 조정·리서치 PoC 통합 → (2) 검증 레이어 정형화(계산+근거) → (3) 전략 Agent 신규 → (4) 사내 보안·배포.

## 4. 면접 무기

### 4-1. 면접 훅 (정체성 선언)
> **"감사로 검증을 배운 회계사가, 신뢰할 수 있는 세무 전략 AI를 만듭니다."**

### 4-2. "더존이 이미 하잖아?" 방어 스크립트
> "네, 더존은 *컴플라이언스를 표준화*했습니다. 그래서 회계사의 가치는 더존이 못 하는 *전략·복잡 판단*으로 이동했고, 제 솔루션은 바로 그 지점 — 안진이 파는 고부가 자문 — 을 AI로 확장합니다. **더존은 데이터를 만들고, 저는 그 위에서 판단을 돕습니다.**"

### 4-3. 정직성 전략 (세무 깊이 이슈)
> "세무 전문성은 쌓는 중입니다. 대신 **감사로 단련한 검증력 + AI**로 빠르게 메우고, **과세·방어 양면 + 회계사 최종판단(HITL)** 구조로 과신을 방지합니다."

## 부록 A. 회계사 토의용 — 열린 논의거리
- 절세 소재 1개 최종 확정(가볍게 — 세액공제 유불리 유력) · 목업 화면 수 · 기존 PoC 재활용 범위

## 부록 B. 8개사 벤치마크 핵심 요약 *(전문: `경쟁사_AI_벤치마크_분석.md`)*
- **업계 정석** = Skills + grounding(근거 인용) + 팩트체커 검증 + HITL/Agentic + 맥락 메모리 → **본 설계와 일치**.
- **차용 카피**: LexisNexis(Claude+Skills 패러다임) · 네플라("사고 과정을 담은 AI"·어쏘 비유) · LBOX("법인세 업무 OS"·근거 가시화) · 슈퍼로이어("세무 팩트체커"·거래처 메모리) · Copilot(KPI 틀·MS 스택 접목) · AiLex(웻지·PDF→데이터 추출).
- **우리만의 영역**: 계산층 Ground Truth 검증 + 회계사 직접 개발(8개사 공백).
