What · Why · How — 설계서 v2

법인세 전략 세무 AI

1차 목적 · 딜로이트 안진 Tax/세무본부 합격 — "감사로 검증을 체화한 회계사가 AI를 직접 설계한다"
포지셔닝 · 전략층 상향(더존 위층) + 구조 중심 데모
근거 · 법률·세무 AI 8개사 벤치마크 + 타겟 도출 대화
v1 → v2 변경점: 더존이 컴플라이언스 "토탈"을 이미 장악 → 정면경쟁을 버리고 전략층(절세 전략 시나리오 생성기)으로 상향. 조정·리서치 PoC는 실력 증거로 재배치.

00 Context — 배경

  • 지원자: RSM 신한회계법인 2년차 KICPA (실무는 외감·감사 중심).
  • 이력: 안진 감사부문 지원 → 불합격 → 이번엔 Tax/세무본부로 전환 지원.
  • 전환: AI 개발 몰입 → 세무조정 자동화 + 세법 리서치 PoC 직접 개발.
  • 벤치마크: 법률·세무 AI 8개사 정밀 분석(넥스트·LexisNexis·네플라·LBOX·슈퍼로이어·더존·AiLex·Copilot).

01 WHY — 왜 만드는가

1-1. 시장의 진실 (벤치마크가 알려준 것)

  • 컴플라이언스는 이미 정복됨: 더존 ONE AI가 법인세무조정·신고·일반 Q&A를 무료·ERP연동·대량으로 제공("3시간→5분"). 정면경쟁 = 패배.
  • 업계가 비워둔 자리: 더존·AiLex까지 모두 "AI는 반복, 사람은 전략" → 고부가 전략·복잡 판단은 사람 몫으로 남겨둠.
  • 그 빈 자리 = 정확히 딜로이트 안진이 파는 영역. 확장 안 되는 고부가 자문을 AI가 거드는 것이 가치.

1-2. 왜 안진(Tax 본부)에 자산인가

  • 반복은 더존에 맡기고 회계사를 고부가 전략 자문에 재배치 + 그 업무를 표준화·재현·근거화.
  • "AI를 쓰는 법인"을 넘어 "AI를 만들 줄 아는 회계사" 보유. 빅4 M365·Copilot 스택과 접목 가능한 세무 레이어.

1-3. 왜 내가 — "감사로 검증을 체화한 회계사"

  • 회계사 × AI 직접 개발 = 희소 교집합. 어디가 쟁점이고 어디서 환각이 위험한지 안다.
  • 감사 배경 = 숨은 무기: 검증·직업적 회의·데이터 정합성·오류 적발 = 8개사 누구도 못 가진 "계산층 Ground Truth 검증"의 원천.
  • 작년 탈락 후 1년간 PoC로 증명(조정·리서치).

02 WHAT — 무엇을 만드는가

정의 · "감사로 검증을 체화한 회계사가 만드는, 검증 가능한 법인세 전략 AI." 절세 전략 시나리오를 생성하되, 각 방안의 과세 리스크와 방어논리를 근거와 함께 검증해 제시. 최종 판단은 회계사(HITL).

2-1. 3대 기능 블록 — 전략을 킬러로 상향

블록역할성격상태
① 세무조정 자동화실력 증거 — "더존이 회사 차원에서 하는 걸 나는 혼자 만든다"계산층PoC
② 세법 리서치실력 증거 + 전략의 근거 공급해석층PoC
③ 절세 전략 시나리오 생성기★ 킬러 — 과세·방어 양면 + 근거 + 검증판단층신규

2-2. 차별점 — "검증 가능한 세무 전략 AI" (8개사 대비)

  • 업계 정석(Skills/워크플로 + grounding·인용 + 팩트체커 + HITL/Agentic + 맥락 메모리)과 본 설계가 정확히 일치 → 정당성 확보.
  • 아무도 못 가진 우리 영역: 정답이 존재하는 세무 계산층 Ground Truth 검증 + 회계사 직접 개발. (법률 6사=해석층 인용검증 / 더존=공제 적용확인 / 계산검증·고차 전략판단은 공백)
  • 핵심 차별 3축: ① 과세·방어 양면 ② 검증 가능(계산+근거) ③ 회계사 직접 개발.

2-3. 킬러 데모 — 절세 전략 시나리오 생성기 (구조 중심)

입력가결산 재무데이터 + 상황 설명 텍스트 (둘 다)
처리절세 시나리오 생성 → 각 방안별 과세논리 vs 방어논리 양면
근거실제 법령·예규·판례 인용 + 출처표기
검증① 절세효과 계산 검증 + ② 방어논리 근거 검증
판단AI는 선택지·수치·근거만, 최종 판단은 회계사(HITL)
소재가볍게(예: 세액공제 유불리) — "작동 구조"를 보여주는 데 집중

왜 "구조 중심"인가: 2년차가 특정 절세 주제로 깊이 경쟁하면 후벼파임. 시스템을 설계했다는 "구조" 자체가 "AI 만드는 회계사" 정체성의 진짜 flex.

03 HOW — 어떻게 만드는가

3-1. 아키텍처 (기준 골격을 법인세 전략으로 확장)

[데이터·컨텍스트]  가결산 재무·전표 · 과거 신고/조정내역(거래처 단위 메모리) · 국가법령정보 MCP · 예규·판례 DB
        │
[오케스트레이션]  Claude Code ── 작업 분해 · 에이전트 병렬 · 결과 통합 (= LexisNexis "Work" / 슈퍼로이어 "계획→결과물")
        │
   ┌────┼─────────────────────────────┐
[에이전트] ① 조정 Agent(PoC)  ② 리서치 Agent(근거 공급)  ③ ★전략 Agent(절세 시나리오: 과세 vs 방어 + 근거 인용)
        │
[검증]   ① 계산 Ground Truth 대조   ② 근거(법령·판례) 출처·실재 검증   ③ human-in-the-loop
        │
[산출]   절세 시나리오 리포트(방안별 효과·과세리스크·방어논리·근거) · 자문메모(docx) · 자문기록 저장

3-2. 신뢰성 설계 (면접 방어)

계산 검증(감사 DNA) · 절세효과·세법 한도를 코드 Ground Truth와 대조, 불일치 자동 플래그 → "세무 팩트체커/검산기"(슈퍼로이어 팩트체커의 세무판, 계산이라 더 강함).

근거 검증·출처표기 · 방어논리의 법령·판례 번호 의무 인용(LBOX·슈퍼로이어식 가시화).

과세·방어 양면 · 리스크까지 스스로 까는 구조 → 깊이 의심 방어 + 감사적 회의 증명.

HITL · AI는 시나리오·수치·근거까지, 결정·서명은 회계사.

보안 · 고객 재무정보 민감 → 사내 보안·접근통제·프라이빗 배포(AiLex 폐쇄형·슈퍼로이어 비학습 참조).

3-3. 정량 효과 (ROI 틀 — Copilot KPI 차용)

절세 시나리오 도출·근거 리서치·자문메모 초안 시간의 절감률(%)을 데모에 수치로 표기.

3-4. 증거와 로드맵

  • PoC(증거): 작동하는 세무조정 자동화 + 세법 리서치.
  • 면접 전 산출: 설계도 + 화면 목업(2~3개 흐름). 작동 데모는 다음 단계.
  • 로드맵: 조정·리서치 PoC 통합 → 검증 레이어 정형화 → 전략 Agent 신규 → 사내 보안·배포.

04 면접 무기

면접 훅 (정체성 선언)

"감사로 검증을 배운 회계사가,
신뢰할 수 있는 세무 전략 AI를 만듭니다."

"더존이 이미 하잖아?" 방어

"네, 더존은 컴플라이언스를 표준화했습니다. 그래서 회계사 가치는 전략·복잡 판단으로 이동했고, 제 솔루션은 바로 그 지점 — 안진이 파는 고부가 자문 — 을 AI로 확장합니다. 더존은 데이터를 만들고, 저는 그 위에서 판단을 돕습니다."

정직성 전략 (세무 깊이)

"세무 전문성은 쌓는 중입니다. 대신 감사로 단련한 검증력 + AI로 빠르게 메우고, 과세·방어 양면 + 회계사 최종판단(HITL) 구조로 과신을 방지합니다."

A·B 부록

A. 회계사 토의용 — 열린 논의거리

  • 절세 소재 1개 최종 확정(세액공제 유불리 유력) · 목업 화면 수 · 기존 PoC 재활용 범위
  • 데이터 접근(거래처 메모리: ERP 연동 vs 수기) · 검증 정형화 수준 · 사내 보안 요건 · 정량 ROI 수치

B. 8개사 벤치마크 핵심 (전문: 경쟁사_AI_벤치마크_분석)

  • 업계 정석 = Skills + grounding(근거 인용) + 팩트체커 + HITL/Agentic + 맥락 메모리 → 본 설계와 일치.
  • 차용 카피: LexisNexis(Claude+Skills) · 네플라("사고 과정을 담은 AI"·어쏘) · LBOX("법인세 업무 OS"·근거 가시화) · 슈퍼로이어("세무 팩트체커"·거래처 메모리) · Copilot(KPI 틀·MS 스택 접목) · AiLex(웻지·PDF→데이터).
  • 우리만의 영역: 계산층 Ground Truth 검증 + 회계사 직접 개발(8개사 공백).
