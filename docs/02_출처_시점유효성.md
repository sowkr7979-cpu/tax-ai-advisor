# 章 02 — 출처 · 인용 · 시점 법적유효성 (Provenance / Citation / Temporal Legal Validity)

> **왜 ERD보다 앞인가**: 세무 결론은 **"어느 시점에 유효한 어느 법령 버전"** 에 묶인다. 이 모델이 없으면 인용은 그럴듯한 URL 문자열에 불과하고, 답변을 사후 재현·검증할 수 없다(Codex 핵심 지적).
> **연결**: `04_ERD`의 `LegalSource/ProvisionVersion/Citation` 골격 · `05_RAG`·`06_Web`의 메타데이터 · `08_환각방지`의 인용 게이트 · `01_보안`의 재현성.

---

## 1. 핵심 원칙 3가지

1. **무근거 결론 금지**: 모든 *법적·세무적 단정*은 하나 이상의 **버전 박힌 소스객체**를 인용해야 한다. (강제는 `08_환각방지`.)
2. **인용은 버전을 가리킨다**: `Citation`은 raw URL/자유텍스트가 아니라 `ProvisionVersion`(시행일 버전)·`Ruling`·`CasePrecedent`·`SourceSnapshot` 을 가리킨다.
3. **시점 유효성**: 결론은 *적용 시점*(거래일/귀속연도/신고일/현재 자문일) 기준으로 유효한 법령 버전에 묶인다. 청킹·메타데이터만으로는 부족하다.

---

## 2. 한국 세무 특유의 시점 문제 (왜 어려운가)

| 개념 | 문제 | 모델링 포인트 |
|---|---|---|
| **시행일(施行日)** | 법령은 공포일 ≠ 시행일. 개정마다 시행일이 다름 | `ProvisionVersion.effective_from/to` |
| **부칙·경과규정(附則)** | "이 법 시행 전 개시한 사업연도분은 종전 규정" 같은 경과조항 | `EffectiveDatePeriod` + `transition_rule` 플래그 |
| **귀속연도 vs 신고연도** | 2025 귀속 법인세를 2026.3 신고 — 법인세는 *귀속(사업연도)* 기준이 원칙이나 **쟁점마다 기준일이 갈린다**(거래일·사업연도 개시/종료일·신고일·처분일·경정청구일) | 쟁점마다 `applicable_basis` **열거 선택·기록**(PROV-013) |
| **소급·불이익 금지** | "납세자에게 유리하면 소급"은 **일반 원칙이 아님**(Codex 교정). 부칙의 적용례·경과조치, 조세법률주의, 신뢰보호, **불이익 소급과세 금지**가 함께 작동 | 부칙 근거·명시적 소급규정 있을 때만, **자동 적용 금지**(PROV-014) |
| **예규·해석 변경** | 같은 조문에 대한 해석이 예규/판례로 바뀜 | `Ruling`/`CasePrecedent`에 `issued_date`·`supersedes` |
| **개정 추적** | korean-law-mcp가 최신/특정 시점 버전을 주는지 불확실 | `SourceSnapshot` + 해시 + 갱신 모니터(=`07_API`) |

> **결론**: "이 비용 손금 되나?"의 답은 **"어느 사업연도냐"** 에 따라 달라진다. 시점을 묻지 않는 답은 틀린 답이다.

## 3. 소스객체 모델 (Versioned Source Object)

모든 권위 출처는 **버전과 시점**을 가진 객체로 표준화한다.

### 3-1. 법령 (`LegalSource → LegalProvision → ProvisionVersion` + `TransitionRule`)
- `LegalSource`: 법령 단위(법인세법, 시행령, 시행규칙, 조특법…). `source_type`, `authority_rank`.
- `LegalProvision`: 조문 단위(제19조의2 등). 상위 위임관계(`delegates_to`).
- `ProvisionVersion`: **시행일 버전**. `text` · **`promulgated_date`(공포일)** · `effective_from` · `effective_to` · **`amended_by`(개정 법률·문서번호)** · `amendment_reason`(개정이유) · `snapshot_id`(원문 캡처) · `hash`.
  - **공포일 ≠ 시행일** 분리 보존. 개정문서번호·적용례 누락 시 결론 제한(PROV-016).
- **`TransitionRule`(부칙 적용례·경과조치 — 독립 객체, Codex)**: `provision_version_id` · `applies_when`(사업연도 개시일/종료일/거래일 조건) · `rule_text` · **기계 판정 가능 조건식**. → "이 법 시행 전 개시한 사업연도분은 종전 규정" 같은 부칙을 *플래그가 아니라 판정 가능한 객체*로.

### 3-2. 예규·질의회신 (`Ruling`)
- `doc_no`(문서번호), `issued_date`, `issuer`(기재부/국세청), `issue`(쟁점), `facts`, `holding`(회신요지), `reasoning`, `related_provisions`, `supersedes`/`superseded_by`.
- **추가(Codex)**: `binding_limit`(예규의 **법적 구속력 한계** — 과세관청 내부해석이며 법원을 구속하지 않음), `internal_change_date`(과세관청 해석 변경일 — 신뢰보호 판단용), `fact_match_required`(납세자 **사실관계 동일성** 충족 시에만 원용 가능). → "회신요지"만 떼어 단정 인용하는 것을 방지.

### 3-3. 판례·심판례 (`CasePrecedent`)
- `case_no`(사건번호), `court`(대법원/조세심판원), `decided_date`, `issue`, `holding`, `reasoning`, `cited_provisions`, `status`(확정/계류).

### 3-4. 웹/외부 캡처 (`SourceSnapshot`)
- `url`, `canonical_title`, `publisher`, `published_date`, `effective_date`(가능 시), `retrieved_at`, `extraction_method`(HTML/PDF/HWP/OCR), `content_hash`, `official`(공식출처 여부).
- **원칙**: 웹은 *발견*용. 권위 출처(법령·예규·판례)로 **승격(promote)** 될 때만 결론 근거로 인정 → `06_Web`.

## 4. 인용 모델 (`Citation`)

답변의 각 *주장 문장*은 `Citation`으로 근거에 연결된다.

```
SourceAnswer ──< Citation >── ProvisionVersion | Ruling | CasePrecedent | SourceSnapshot
              │
              ├ claim_span        (답변 내 주장 위치)
              ├ source_locator    (조/항/호/목, page, paragraph)
              ├ quote             (지지하는 원문 발췌)
              ├ applicable_basis   (거래일/귀속연도/신고일 등 — 어느 시점 기준인지)
              │   └ ※ 문자열이 아니라 Matter/TaxYear/FactPattern의 *실제 날짜 사실*에
              │       기계적으로 연결(basis_kind + 참조 객체ID) → 시점 검증 자동화(Codex)
              ├ support_type      (직접근거 / 유추 / 반대견해)
              ├ confidence        (해당 인용의 신뢰도)
              └ authority_rank    (권위 순위: 법령>시행령>예규>판례>실무서>웹)
```

- **pinpoint 인용 의무**: 조문/문단 위치까지(법 제○조 제○항 제○호). "법인세법에 따라" 수준은 미달.
- **entailment 원칙**: 인용 원문이 **그 주장을 실제로 지지**해야 함(개수 아님) → 채점은 `09`에서 entailment로.
- **시점 표기 의무**: 각 인용은 `applicable_basis`를 달아 "2025 귀속연도 기준 유효 조문"임을 명시.

## 5. 권위 위계 & 충돌 처리 (종합 단계의 조정 기준)

- **권위 위계**: 법률 > 시행령 > 시행규칙/고시 > (해석) 예규·질의회신·판례·심판례 > 라이선스 실무서 > 웹.
- **단, 단순 서열이 아님 + override 오해 금지(Codex 교정)**: 시행령은 **법률의 위임 범위 내에서 보충**할 뿐 법률을 *override 하지 않는다*. 예규·판례·심판례는 **해석·구체화**이지 법령 본문을 무효화하지 않는다(예규=구속력 한계, 판례·심판례=확정 여부 변수). → 종합 시 *위임·해석 관계 + 시점 + 사실관계 동일성*을 함께 본다.
- **이 권위 위계가 쓰이는 곳**: (a) **종합 단계**의 claim 정합·tie-break(가중혼합 ✕, 다수결 ✕), (b) **각 소스 *내부*** 검색·재랭킹의 신뢰도 신호. *소스 간 결합은 종합으로*(50/30/20 산술가중 폐기 → `README §5`).
- **충돌(`ConflictFlag`)**: 소스 간 불일치를 **평균내지 말고 표면화**. 결론을 단정하지 않고 **회계사 검토 항목**으로 올린다(= `08`).
- **"세 답 후 종합"**: 3소스가 각각 완결 답변(`SourceAnswer`) → claim 단위 일치/충돌 표시 → 종합 에이전트가 권위·시점 기준으로 조정(`08 §5`).

## 6. 시점 유효성 처리 흐름

```
쟁점 입력 + 적용시점(거래일/귀속연도/신고일) 결정
        │  (Intake에서 귀속연도·거래일 확보 — 없으면 abstain하고 되물음)
        ▼
법령 검색 → effective_from ≤ 적용시점 < effective_to 인 ProvisionVersion 선택
        │  └ ※ 경계 규약 명시: effective_from=inclusive, effective_to=exclusive(개정 전일/폐지일 경계 테스트로 검증, PROV-012)
        │  └ 부칙·경과규정 있으면 TransitionRule의 조건식으로 *기계 판정*(자동 단정 금지)
        ▼
예규·판례는 issued/decided_date 와 supersede 관계로 *해당 시점 유효 해석* 선별
        ▼
답변에 applicable_basis 명시 + 다른 연도면 결론이 달라질 수 있음을 고지
```

- **핵심 가드**: 적용시점이 불명확하면 **결론 금지 → 되물음(abstain)**. (예: "어느 사업연도 기준인가요?")

## 7. PROV- 기능요구사항 (요약 — 전체는 `03_RFP`)

| FR-ID | 요구 | 수용기준(발췌) | 우선순위 |
|---|---|---|---|
| `PROV-001` | 법적 단정은 1개 이상 버전 박힌 소스객체 인용 | 무인용 단정 0건(`08` 게이트와 연동) | P0 |
| `PROV-002` | `Citation`은 URL/자유텍스트가 아니라 소스객체를 참조 | 모든 인용이 객체ID로 해석됨 | P0 |
| `PROV-003` | 법령은 `ProvisionVersion`으로 시행일 버전 관리 | 동일 조문 2개 연도 질의 → 다른 버전 인용 | P0 |
| `PROV-004` | 인용에 pinpoint(조/항/호/목·문단) 보존 | 위치 없는 인용 거부 | P0 |
| `PROV-005` | 인용에 `applicable_basis`(적용시점) 명시 | 시점 미표기 결론 감점 | P0 |
| `PROV-006` | 적용시점 불명확 시 결론 금지·되물음 | "어느 연도?" abstain 동작 | P0 |
| `PROV-007` | 예규·판례의 supersede/issued_date 추적 | 폐지·변경된 해석 인용 시 경고 | P1 |
| `PROV-008` | 부칙·경과규정 플래그(자동 단정 금지) | 경과규정 케이스 → 검토항목 상승 | P1 |
| `PROV-009` | 소스객체 해시·snapshot으로 재현성 | 답변이 쓴 법령버전 사후 복원 | P1 |
| `PROV-010` | 인용 원문 entailment(주장 지지) 검증 | 비지지 인용 적발(`09` 채점) | P1 |
| `PROV-011` | 부칙 적용례·경과조치를 `TransitionRule` 독립 객체로(기계 판정) | 사업연도 개시/종료/거래일 조건 판정 | P1 |
| `PROV-012` | `effective_to` inclusive/exclusive 명시 + 경계 테스트 | 개정 전일·폐지일 경계 통과 | P0 |
| `PROV-013` | 쟁점별 기준일 선택·기록(거래일/귀속/사업연도/신고/처분/경정청구) | basis 미선택 결론 차단 | P0 |
| `PROV-014` | 유리 개정 소급은 자동 적용 금지(부칙·신뢰보호 검토 표시) | 소급 자동적용 0건 | P0 |
| `PROV-015` | 예규는 구속력 한계·폐지/변경·사실관계 동일성 함께 표시 | 사실 불일치 예규 단정 인용 차단 | P1 |
| `PROV-016` | 개정 추적(공포일·시행일·적용례·개정문서번호) 보존, 누락 시 결론 제한 | 메타 누락 시 abstain | P1 |

## 8. 면접 한 줄
