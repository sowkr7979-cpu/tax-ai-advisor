# 章 06 — Web Research (최신 공식근거 수집기)

> **대원칙(Codex)**: Web Research는 **"답변 생성기"가 아니라 "최신 공식근거 수집기"** 다. 검색엔진은 **발견 도구**일 뿐 **권위 소스가 아니다.** 결론 근거가 되려면 권위 소스객체로 **승격(promote)** 되어야 한다.
> **왜 External API와 별도 章인가**: Web Research는 *제품 의미론*(공식소스 정책·query 계획·증거 스코어·충돌탐지·최신성), `07_API`는 *인프라*(credential·retry·rate limit·cost). 섞으면 "수집기 vs 답변기" 경계가 무너진다.
> **연결**: 소스객체·시점=`02_출처` · 충돌·검토항목=`08_환각방지` · 검색 클라이언트(Tavily/Brave)=`07_API`(src/ai) · 격리(웹은 공유 `L0`)=`01_보안`.

---

## 1. 역할 (3소스 중 ③ — **독립 SourceAnswer**, 가중 폐기)

- 법령 원문(①, 법령MCP)·내부 RAG(②)가 **권위·축적**이라면, 웹(③)은 **최신성·맥락 보완**: 개정 동향·신규 예규·보도자료·해석 변화.
- 웹은 **③(WEB) 채널만으로 독립 완결 답변(`SourceAnswer`)** 을 내되, **종합 단계에서 권위·시점으로 조정**(법령 부재를 대체 못함 → `08 §5-0` 법령부재 케이스).
- **단독 결론 금지**: 웹만으로 세무 단정 ✕. 반드시 법령/예규 권위 소스로 확인.

## 2. 파이프라인

```
① Query Planner   세목·귀속연도·쟁점·법령 키워드로 검색어 생성 + 한국어 확장
        ▼
② Source Policy(사전)  허용 도메인 우선·비공식 배제 질의 구성
        ▼
③ Search API      Tavily(1순위) + Brave(보조) + 공식소스 커넥터
        ▼
④ Page Extraction  snippet 아님 — 원문 추출(HTML/PDF/HWP/OCR) → SourceSnapshot(버전·해시)
        ▼
⑤ Source Policy(사후)  검색결과가 mirror/요약/블로그/구버전이면 여기서 탈락
        ▼
⑥ Source Scoring   공식성·최신성·쟁점관련성·법적권위·①②와 일치여부
        ▼
⑦ Conflict Check   법령MCP·내부RAG와 충돌 표시(평균 금지)
        ▼
⑧ Promote          공식·검증된 것만 권위 소스객체로 승격 → 결론 근거 후보
```

## 3. ① Query Planner + 한국어 확장

- 입력: 쟁점 + **세목·귀속연도·거래일**(시점) + 법령 키워드.
- **한국어 query expansion(필수)**: 법령 정식명칭·약어, **조문번호 형식 변형**(제19조의2 / 19-2 / 법19②), 서식명, 동의어, 기간/연도 변형. → 일반 검색이 한국 공식자료를 잘 못 찾는 문제 보완.

## 4. ②⑤ Source Policy Filter (사전 + **사후**)

- **허용(우선)**: 국세청 · 기획재정부 · 조세심판원 · 법제처(국가법령정보) · 대법원/법원 · 공식 보도자료.
- **배제/저신뢰**: 블로그 · 카페 · 광고성 세무 콘텐츠 · 출처불명 · 미러/요약 재가공.
- **핵심(Codex)**: 필터를 **query 단계뿐 아니라 retrieval 後에도** 적용. 검색 API는 질의와 무관하게 mirror·블로그·구버전을 반환할 수 있으므로, **추출 후 도메인·공식성·시점 재검증**.

## 5. ③ 검색 소스 선택 (ADR 포함)

| 소스 | 역할 | 비고 |
|---|---|---|
| **Tavily** | 1순위 에이전트 검색 | `include_domains`로 공식출처 제한, `time_range`/`topic` 활용. advanced=2 credits(관련성↑·비용↑), basic=1 |
| **Brave Search** | 보조 | 자체 인덱스·freshness·site/filetype 연산자·LLM context endpoint |
| **공식소스 커넥터** | **권위 확보** | 국세청·법제처·조세심판원 등 **직접 연계/스크래핑**(법·기술·라이선스 허용 범위). 검색API의 커버리지 공백(동적페이지·PDF·구 예규·기본통칙) 보완 |
| ~~Google Custom Search~~ | **제외** | 신규고객 차단·2027 전환 → **ADR로 제외 사유 문서화 + recall 마일스톤에서 재검토** |

> **Codex 보강**: Tavily/Brave는 **discovery**, 권위는 **공식 커넥터**. 검색API가 stale·비공식·재가공 결과를 상위로 줄 수 있으니 "검색 1위 = 정답" 금지.

## 6. ④ Page Extraction → SourceSnapshot

- snippet만 쓰지 않고 **원문 페이지 추출**. PDF·**HWP**·스캔본은 OCR(`07_API`).
- 저장(`SourceSnapshot`, = `02_출처`): `url` · `canonical_title` · `publisher` · `published_date` · `effective_date`(가능 시) · `retrieved_at` · `extraction_method` · `content_hash` · `official` 플래그.

## 7. ⑥ Source Scoring

후보별 점수(웹 소스 **내부** 스코어링): **공식성 · 최신성 · 쟁점 관련성 · 법적 권위 · ①②(법령MCP·내부RAG)와의 일치 여부**.
- **최신성 ≠ 적용시점 유효성(Codex·`WEB-012`)**: 두 점수를 **분리 저장**. "가장 최근 게시물"이 "그 사업연도에 유효한 근거"는 아니다.
- 비공식·구버전·불일치는 강등. 공식·시점유효·일치는 승급.

## 8. ⑦ Conflict Detection

- 웹 결과가 법령MCP·내부RAG와 **충돌하면 `ConflictFlag`** 로 표시(평균·혼합 금지).
- 충돌 시 **결론 단정 금지 → 회계사 검토항목**으로(`08_환각방지`).

## 9. ⑧ Promotion (승격)

- **승격 검증(Codex·`WEB-011`)**: 웹 후보가 결론 근거가 되려면 **공식 원문 URL·발행기관·`retrieved_at`·`content_hash`** 를 갖추고, **법령 원문(①)/내부RAG(②)와 대조**되어 일치·진정성이 확인되어야 한다. (검색 스니펫·재가공본만으로 승격 ✕.)
- 공식 출처에서 확인되고 시점이 유효한 것만 **권위 소스객체(Ruling/ProvisionVersion 등)** 로 승격 → 비로소 결론 근거.
- 승격 못한 웹 자료는 "참고·동향"으로만 표기.

## 11. 면접 한 줄

> "웹 검색은 *답을 만드는 곳*이 아니라 *최신 공식근거를 찾아오는 곳*입니다. 그래서 Tavily·Brave는 발견용으로만 쓰고, 결론 근거는 국세청·법제처 같은 **공식 출처로 승격된 것만** 인정합니다. 블로그·카페는 기본 배제하고, 법령 원문과 충돌하면 **단정하지 않고 회계사 검토로** 넘깁니다."
