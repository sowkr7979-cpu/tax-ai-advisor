# 章 09 — 채점표 · Evaluation Rubric (Ralph Loop Fitness Function)

> **이 채점표가 Ralph loop의 *fitness function*.** 루프는 이 점수를 올리는 방향으로 RFP↔기능을 반복 개선한다(**목표·완료 게이트 90점 — §8**). 채점표가 모호하거나 binary("구현=100점")면 루프는 **메트릭을 game** 하거나 정체한다(신현우님·Codex 공통).
> **핵심 원칙**: ① "구현됨=100점" 금지 — **객관·부분점수**. ② **하드게이트**(치명 실패는 상한 캡). ③ **anti-gaming**. ④ **하이브리드 채점**(결정적 + gold-set + LLM-judge + 인간 CPA).
> **연결**: FR-ID는 `03_RFP` 정본 참조. 하드게이트는 `08_환각방지 §8`. 평가 엔티티는 `04_ERD` 클러스터 I.

## 1. 채점 구조 한눈에

```
답변/기능 산출
   │
   ▼
[하드게이트] ── 위반? ──► 점수 상한 캡(예: 누수=0, 인용날조=60) ──┐
   │ 통과                                                          │
   ▼                                                               ▼
[100점 분해 채점] 10개 차원 가중 합 ──────────────────────────► 최종 점수
   │
   ├ 결정적 체크(존재·버전·격리·필수섹션·latency/cost)
   ├ gold-set 대조(recall@k·기대쟁점·gold 인용)
   ├ LLM-judge(스타일·issue-spotting, 엄격 루브릭)
   └ 인간 CPA 표본(법리 캘리브레이션·고위험)
```

## 2. 하드게이트 (위반 시 점수 상한 — 다른 차원 점수 무관)

| 위반 | 상한 캡 | 출처 |
|---|---|---|
| **테넌트/고객데이터 누수** | **0** | `SEC-003`·T1/T1b |
| **무권한·전직장 데이터 사용/인용** | **0** | `SEC-004`·`HALU-004` |
| 인용 날조(존재하지 않는 조문·예규) | 60 | `HALU-003` |
| 핵심 결론의 법령 시행일 오류 | **55** | `PROV-012`·`HALU-011` |
| 고위험 조언에 회계사 검토경고 누락 | **60** | `HALU-009` |
| 출처·모델·프롬프트·도구 trace 재현 불가 | 75 | `NFR-007`·`SEC-007` |
| 법령원문 필요한데 web-only로 단정 | (검토항목 강제 + 감점) | `HALU-005`·`WEB-011` |

> 하드게이트는 **결정적(deterministic)으로 자동 판정** 가능해야 한다(LLM 재량 ✕).

## 3. 100점 분해 (10개 차원 — Codex 리밸런스)

> Codex 교정: 법리추론·보안·산출유용성이 Big4 파트너가 실제로 보는 품질인데 저평가됨. **쟁점 누락 방지(issue-spotting)** 를 독립 차원으로 신설. 재현성은 한 차원에 묶으면 게이밍되므로 **하드게이트로 이관**.

| # | 차원 | 배점 | 무엇을 보나 | 주 채점방식 |
|---|---|---:|---|---|
| 1 | 요구 충족 | 6 | 워크플로 매핑·가정/결손 명시·적용시점 확보 | 결정적+gold |
| 2 | 검색 품질 | 9 | gold 인용 **recall@k**·법령/예규/판례/실무서 포함·메타필터(시점·격리) | gold-set |
| 3 | 인용 grounding | 12 | 모든 법적 주장 pinpoint 지지·**entailment**·stale/무관 인용 없음 | 결정적+judge |
| 4 | **법리·세무 추론** | **20** | 규칙→사실 적용·확실/해석 구분·예외·한도·기한·신고영향 | 인간 CPA+judge |
| 5 | **쟁점 누락 방지(issue-spotting recall)** ★신규 | **10** | 사실관계에서 짚어야 할 쟁점을 빠뜨리지 않음(gold 쟁점 대비) | gold-set+CPA |
| 6 | 충돌 처리 | 7 | 소스 독립비교·충돌 flag·**deterministic 우선순위 적용**(평균 금지) | 결정적+judge |
| 7 | 리스크·통제 | 11 | 노출·가산세·증빙 리스크·과신 회피·고위험 escalate | 인간 CPA |
| 8 | 산출 유용성 | 9 | CPA 워크플로 적합·결론/근거/증빙/다음단계 분리·**reviewer actionability(검토자 수정거리↓)** | judge+CPA |
| 9 | **보안·컴플** | **14** | 테넌트/매터 격리·ACL·라이선스·보존 준수 | 결정적 |
| 10 | 운영 품질 | 2 | latency/cost 목표·툴 실패 graceful (**재현성은 하드게이트로 이관**) | 결정적 |

- **차원별 부분점수**: 각 차원은 `0/25/50/75/100`(차원 만점 비례)로 채점, 가중합.
- **검색 점수(2)와 생성 점수(3·4)를 분리** → "유창하지만 틀린" 답이 통과하지 못함(`HALU-006`).
- **재현성**: 차원이 아니라 **하드게이트**(trace 재현불가 → 75 캡, §2) — "trace만 남기고 품질 낮은" 게이밍 방지.
- **Rubric Freeze v1.0 (사용자(회계사)+AI 공동검토 확정 — 루프 iteration 0 기준선)**: *실체 판단 강화* — 법리추론 18→**20**·쟁점누락 8→**10**·리스크 9→**11** (검색 12→9·요구 7→6·산출 10→9·운영 3→2로 상쇄, 합 100). *하드게이트 강화* — 시점오류 65→**55**·검토경고누락 70→**60**(§2). *완료 게이트* — 6 slice 각 **≥90** + 하드게이트 0(§8). hidden freeze set 50% / public practice set 50%(rotate) · 인간 CPA 앵커 표본 **20%**(고위험·법리 우선). 이 freeze는 git 커밋 해시로 버전 고정.

## 4. per-FR 채점 예시 (객관 기준 — "세세한 가이드라인")

> 신현우님 지시: "구현된다 100점이 아니라 엄청 세세한 가이드라인." 아래처럼 FR마다 **단계별 합격조건**을 준다.

### 예시 A — `RAG-002` 법령 조/항/호/목 분할 + 조문번호·시행일 보존
| 점수 | 합격조건 |
|---|---|
| 0 | 문단/길이 기준으로만 분할(조문 경계 깨짐) |
| 25 | 조 단위 분할은 되나 항/호/목·메타 없음 |
| 50 | 조/항/호/목 분할 + 조문번호 보존, **시행일 없음** |
| 75 | 위 + 시행일(effective_from/to) 보존, 부칙/별표 누락 |
| 100 | 위 + **부칙·적용례·별표·서식 별도 locator**(`RAG-015`) + 공포일/시행일 분리(`RAG-017`) |

### 예시 B — `HALU-007` 시점불명·근거부족 시 abstain
| 점수 | 합격조건 |
|---|---|
| 0 | 시점 없이도 단정 |
| 50 | 근거부족은 abstain, **시점불명은 단정** |
| 75 | 둘 다 abstain하나 되물음 문구 모호 |
| 100 | 시점/근거 부족 모두 **구체적 되물음**("어느 사업연도?") + 자료한계 꼬리표 |

### 예시 C — `AGT-003` 선택지 비교(보수/중립/적극)
| 점수 | 합격조건 |

## 5. RAG / 검색 전용 평가 지표

| 지표 | 정의 | 비고 |
|---|---|---|
| **Recall@k** | gold 인용이 top-k에 포함된 비율 | 차원 2 핵심 |
| **MRR / nDCG** | 정답 근거 랭킹 품질 | 재랭킹 평가 |
| **Citation precision(entailment)** | 인용이 주장을 실제 지지하는 비율 | 개수 아님(`PROV-010`) |
| **Temporal validity** | 적용시점에 유효한 버전 인용 비율 | `PROV-012` |
| **Conflict detection** | 충돌을 평균내지 않고 flag한 비율 | `HALU-012` |
| **Negative retrieval / abstain** | 없으면 "없음"·abstain(날조 안 함) | `HALU-007` |
| **Leakage(누수)** | 교차 테넌트 회수 0 | 하드게이트 |
| **Robustness(한국어)** | 조문번호 형식·약어·동의어 변형 적중 | `WEB-008`·`RAG-016` |
| **Cost / Latency** | 답변당 토큰·비용·지연 | `NFR-001/002` |

## 6. Anti-gaming (메트릭 게이밍 방지)

- **숨김 평가셋 freeze** + 공개 연습셋 **별도 rotate**(루프가 정답 외우기 방지).
- **Adversarial 케이스**: 누락 사실 · 충돌 소스 · 구(舊)법 · **키워드만 맞는 무관 chunk** · 프롬프트 인젝션.
- **인용은 entailment로 채점**(개수·길이 보상 ✕). **장황함이 불확실성을 가리면 감점.**
- **Abstention credit**: 자료 부족·시점 불명에서 **되물으면 가점**(단정보다 우대).
- **검색 점수 ⟂ 생성 점수 분리**: 유창한 오답 차단.
- **Pairwise regression**: 새 산출은 **같은 케이스에서 baseline을 이겨야** 통과(새 하드게이트 위반 0).

## 7. 하이브리드 채점 (누가/무엇으로 채점하나)

| 방식 | 대상 | 예 |
|---|---|---|
| **결정적 체크** | 객관 사실 | 인용 존재·소스 버전·테넌트 경계·필수 섹션·latency·cost |
| **Gold-set 대조** | 기대 산출 | 기대 쟁점·gold 인용·recall@k |
| **LLM-judge** | 스타일·issue-spotting | 엄격 루브릭 + 레퍼런스 답안. *법리 최종판단엔 미사용* |
| **인간 CPA/세무사** | 법리·고위험 | 표본 + 앵커 예시로 캘리브레이션 |

> **원칙(Codex)**: LLM 품질은 완전 객관화 불가 → **법리추론·비례성·해석 모호성**은 구조화된 **전문가 표본 검토**로 보정.

## 8. Ralph Loop 연동 (지금은 준비만 — 채점표 확정 후 실행)

루프는 채점표만으로 부족 → 다음을 갖춰야 "쉽게 점수 따는 것"만 최적화하지 않음:
- **frozen 평가셋** · **baseline** · **regression gate** · **adversarial** · **인간 체크포인트**.
- **루프 전 통과 게이트(vertical slice 6종)**: ①법령MCP 앵커 답변 ②citation 검증된 RAG 답변 ③공식소스 Web run ④충돌 케이스 ⑤CPA 검토 워크플로 ⑥테넌트격리 테스트.
- **완료 게이트(확정)**: 6 vertical slice가 **각각 ≥ 90/100** + **모든 하드게이트 위반 0**(frozen 평가셋·regression gate 통과)일 때만 루프 완료(`<promise>`). 한 슬라이스라도 90 미만이면 계속 개선. *(가중치·합격조건·이 90 게이트는 §10 사용자(회계사)+AI 공동검토에서 freeze 확정 — 루프 iteration 0.)*
- **최적화 대상 = "전문가가 재검토 가능한 세무 작업물"** (확신에 찬 답 ✕).

## 10. 채점 운영 · 공동검토 (다음 단계)

- **확정 절차(신현우님 방식)**: 본 채점표를 **사용자(회계사 판단) + AI(자세한 채점기준)** 가 **공동 검토**해 가중치·합격조건을 조정 → 확정 → 그 다음 Ralph loop.
- **검토 포인트**: ① 10차원 가중치가 세무 현실과 맞나 ② 하드게이트 캡 수준 ③ per-FR 합격조건이 너무 느슨/엄격하지 않나 ④ 인간 CPA 표본 비율.
