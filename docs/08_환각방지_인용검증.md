# 章 08 — 환각 방지 · 인용 검증 (Hallucination Prevention & Citation Verification)

> **제품의 신뢰성 코어.** "감사로 검증을 체화한 회계사"의 정체성이 *기능*으로 구현되는 곳. 세무에서 환각은 치명적이므로, 답변은 **게이트를 통과해야만** 사용자에게 간다.
> **연결**: 인용·시점=`02_출처` · 검색 근거=`05_RAG`/`06_웹` · 계산 Ground Truth=`src/`(계산엔진) · 하드게이트 점수=`09_채점표` · 재현성=`01_보안`.

---

## 1. 원칙 — 무근거 결론 금지

- **모든 세무·법적 단정은 근거(소스객체 인용)를 가진다.** 근거 없으면 단정하지 않는다.
- **AI는 결론을 내리지 않는다** — 선택지·수치·근거·보류사항까지. **결정·서명은 회계사(HITL).**
- 4중 방어: **① 계산 검산 ② 인용 검증 ③ 충돌 표면화 ④ abstain + HITL.**

---

## 2. 검증 게이트 (답변 생성 → 게이트 → 사용자)

```
각 SourceAnswer ─► [G1 계산검산] ─► [G2 인용검증] ─┐
(①/②/③ 독립)                                       ├─► [G3 종합·충돌(claim단위)] ─► [G4 시점·abstain] ─► [G5 HITL]
                 │ 불일치           │ 무근거/비지지     │ 소스 충돌            │ 시점불명/근거부족      │ 회계사 검토
                 ▼                  ▼                  ▼                     ▼                     ▼
            빨간 깃발            인용 거부/수정      검토항목으로            결론 보류·되물음         승인·서명
```
> **적용 단위(Codex)**: **G1·G2는 각 `SourceAnswer`에 개별 적용** → **G3 종합 단계에서 claim 단위 충돌 + lineage(추적) 재검증**(`HALU-013/014`). 즉 환각 검사는 *소스별 + 종합*에서 두 번.

## 3. G1 — 계산 Ground Truth 검산 (세무 특화 · 감사 DNA)

> **범위 주의(Codex 교정)**: "세법은 정답이 정해져 있다"는 **과한 표현.** 계산엔진은 *산식*을 검증하지, *사실인정·법적 평가*를 검증하지 못한다. 둘을 **반드시 구분 표시**(`HALU-011`).

| 구분 | 예 | 검증 주체 |
|---|---|---|
| **✅ 산식 검증 가능(GT 대상)** | 접대비 한도·감가상각비·기부금 한도·지급이자 손금불산입·세액공제 산식·인정이자 *계산* | `src/` 계산엔진 ↔ 자동 대조·빨간 깃발 |
| **⚠️ 사실인정·법적평가 필요(GT 불가)** | 특수관계 여부·업무무관성·**시가/인정이자율 *적용 판단***·증빙 적격성·손금 귀속 | **회계사 판단(HITL)** — 계산엔진이 단정 ✕, 검토항목으로 |

- 절세효과·조정금액의 **산식 부분**만 Ground Truth와 대조, 불일치 시 자동 플래그.
- **사실판단 의존 입력**(예: 시가)은 "가정값"으로 표시하고 **가정이 바뀌면 결과가 바뀜**을 고지.
- 차별점: 법률 AI는 *해석*만 검증, TIW는 **검증 가능한 계산까지** 검증(범위를 정직하게 한정). 계산 로그 저장(재현성).

## 4. G2 — 인용 검증 (Citation Verification)

각 주장 문장의 `Citation`을 검사:
- **존재(existence)**: 인용 소스객체가 실제 존재(날조 아님). → 없으면 **하드게이트(날조)**.
- **버전·시점(version)**: 인용이 `ProvisionVersion`(시행일 버전)을 가리키고 `applicable_basis`가 적용시점과 일치(`02_출처`).
- **pinpoint**: 조/항/호·page·paragraph까지. "법인세법에 따라" 수준 미달.
- **entailment(지지)**: 인용 원문이 그 주장을 **실제로 지지**(개수 아님). 비지지 인용 적발 → 수정/거부.
- **출처 권한(license)**: 무권한·전직장 출처 인용 → **하드게이트(0점)**(`01_보안`).

## 5. G3 — 교차 출처 충돌 (3소스 독립답변 → claim 단위 정합)

- 3소스(법령MCP ① · 내부RAG ② · 웹 ③)가 **각각 완결 답변(`SourceAnswer`)** 을 낸다 → **claim(원자 명제) 단위로 일치/충돌/침묵 매핑**(`ClaimAlignment`). **평균·다수결 금지.**
- 충돌 시 `ConflictFlag` + **결론 단정 금지 → 회계사 검토항목**으로 승격.

### 5-0. 앙상블 엣지 케이스 (Codex)
| 상황 | 처리 | 표시 |
|---|---|---|
| 한 소스 **침묵/공백** | 불일치로 보지 않음, 나머지로 진행 + 커버리지 갭 표시. 침묵 소스가 권위라면 confidence↓·HITL | `SourceAnswer.status=SILENT` + "③ 웹 근거 없음" |
| **3자 모두 불일치** | 결정테이블로 claim별 해소 불가 시 **종합의견 보류** + 위험도별 H2/H3 escalate | 소스별 입장 *각각* 표시 + "종합 보류/전문가 검토" |
| **2 합치·1 충돌** | 다수결 ✕ → **권위 먼저**: 소수라도 상위 권위·유효 최신법이면 소수 채택; 하위·사실하자 없으면 종합 + 단서 | 다수/소수·권위비교·"반대 근거" 별도 |
| **①법령 부재, ②③ 합치** | **비권위적 합의**: 실무·웹이 법령을 대체 못 함 → 실무 가이드로만, confidence 캡·고위험 HITL | "법령 원문 근거 미확보" + 실무가이드/법적결론 구분 |

> **핵심**: 종합의견이 보류(abstain)해도 **소스별 답변은 보여준다**(방어가능성 + 유용성 양립).

### 5-1. 충돌 해소 결정 테이블 (deterministic — `rules/`, prompt가 아님; Codex)
충돌 해소는 LLM의 재량이 아니라 **`rules/`의 결정 규칙**으로 처리하고 **결과를 로그**(`HALU-012`). 입력: `authority_rank · 시점 유효성 · 사실관계 동일성 · source_type`.

| 상황 | 결정 |
|---|---|
| 법률 vs 웹/실무서 불일치 | **법률 채택**, 웹/실무서는 참고로 강등 |
| 법률 vs 예규/판례(해석) | 법률 문언 + 해석을 *함께* 제시(예규는 구속력 한계 표시) |
| 같은 조문의 다른 시행일 버전 | **적용시점 유효 버전** 채택(`02 §6`), 타 버전 배제 |
| 예규 vs 예규(신·구) | `supersede`·issued_date로 유효본, 사실관계 동일성 확인(`PROV-015`) |
| 사실관계 불일치 예규 원용 | **원용 불가** 표시 → 검토항목 |
| 해소 불가(권위·시점 동급) | **단정 금지 → 회계사 검토항목**(그대로 노출, 숨기지 않음) |

> 이 테이블이 "법 > 내부 > 웹" 우선순위를 *코드로 강제*하는 지점(README §2의 `rules/`).

## 6. G4 — Confidence 분리 + Abstention

### 6-1. Confidence 계산식 (`ConfidenceScore` 엔티티에 분리 저장 — Codex)
**두 점수를 합치지 않고 분리 저장**한다(`04_ERD` `ConfidenceScore`):
- **retrieval_confidence** = f(top rerank 점수, gold/근거 충분성, **적용시점 유효성 충족 여부**, 인용 entailment 비율). → 근거가 있는가.
- **generation_confidence** = f(인용 커버리지=주장 중 인용된 비율, 충돌 없음, 계산 플래그 없음). → 답이 근거 위에 서 있는가.
- **게이트 규칙**: `retrieval_confidence`가 임계 미만이면 **generation_confidence와 무관하게 abstain**(유창하지만 근거 약한 "fluent wrong" 차단). 두 점수와 abstain 사유를 로그.

- **검색 confidence와 생성 confidence 분리**: 유창하지만 근거 약한 답("fluent wrong")을 거른다.
- **Abstention(되물음)**: 적용시점 불명 / 근거 부족 / 자료 결손 시 **결론 대신 질문**(예: "어느 사업연도 기준인가요?", "○○ 자료가 없어 추정입니다").
- **abstain은 감점이 아니라 가점**(`09` abstention credit) — 모르면서 단정하는 것보다 낫다.

## 7. G5 — HITL · 회계사 검토항목 자동생성

- 답변마다 **"회계사 검토 필요사항"** 을 자동 생성: 충돌 쟁점·시점 가정·계산 플래그·근거 약한 주장·추가 필요자료.
- 검토자 승인/반려·잠금·서명(`01_보안 §5`, `Review/ReviewerDecision`).
- 고객 전달본 ≠ 내부 메모(전략 리스크·과세논리는 내부용).

| `HALU-013` | 한 `SourceAnswer`의 인용 날조 → 그 소스 60 캡 + **종합에 경고 전파** | 소스 캡·종합 경고 동작 | P0 |
| `HALU-014` | 추적 불가(미인용) 종합 claim은 최종 표시 차단 | 무추적 종합 claim 표시 0 | P0 |

## 10. 면접 한 줄

> "감사는 '틀린 걸 잡아내는' 일입니다. 그래서 이 AI는 답을 내기 전에 **다섯 개의 검문소**를 통과시킵니다 — 계산이 맞나, 인용이 진짜로 그 말을 지지하나, 출처들이 충돌하나, 시점을 아나, 마지막은 회계사인가. 모르면 **단정하지 않고 되묻습니다.** 환각이 치명적인 세무에서, 저는 '근거 없으면 결론 없다'를 게이트로 강제했습니다."
